## What 0.2.2 contains

This release supplies complete Python wheels after the attempted 0.2.1 backfill was [rejected by PyPI's 14-day upload limit](0.2.1-wheel-backfill.md). Portable formats, ABI-117 and the Core runtime implementation are unchanged. Python, TypeScript and both Rust crates share version 0.2.2 and the release source above; their tracked lockfiles and exact dependencies are synchronized.

The Rust projection retains `AtomicUsize::fetch_update` with a local deprecation allowance: Rust 1.99 deprecated that alias, while its replacement `try_update` requires Rust 1.95. This keeps the existing edition-2024 compiler baseline and checked retain behavior; the [standard library documents both methods as aliases](https://doc.rust-lang.org/std/sync/atomic/struct.Atomic.html#method.fetch_update).

The Python inventory requires 30 wheels, with cp310, cp311, cp312, cp313, cp314 and cp314t on every platform below, plus one sdist. The initial 0.2.2 publication supplied the 20 wheels for 3.12 and later; the 3.10/3.11 backfill builds the same immutable source tag and uploads only its ten missing filenames. Each installed wheel runs a native payload write/read smoke and the payload suite. Inventory checks reject missing, duplicate or unexpected wheel slots and require the sdist before PyPI upload.

The expanded inventory has 37 package archives: 30 Python wheels, one sdist, three Core SDK bundles, two Rust crates and one TypeScript/WASM npm tarball. The original release manifest and receipt retain their initial 27-archive inventory. The additive [3.10/3.11 manifest](https://github.com/world-in-progress/fastdb/releases/download/v0.2.2/python-310-311-backfill-manifest.json) lists the ten additional wheels, sizes and SHA-256 hashes; its [backfill receipt](https://github.com/world-in-progress/fastdb/releases/download/v0.2.2/python-310-311-backfill-receipt.json) records publication and public-download verification. Core SDK targets are `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin` and `x86_64-pc-windows-msvc`; npm carries the `wasm32` projection. Python wheel coverage and the remaining native SDK platform work are distinguished in [Issue 0001 D4](../issues/0001-portable-payload-deferred-capabilities.md#d4-guaranteed-platforms-beyond-linux-x86-64-macos-arm64-windows-x64-and-wasm32).

## Trusted publishing and recent-tag backfills

PyPI remains bound to `world-in-progress/fastdb`, workflow `pypi_publish.yml`, with no environment configured. Tag pushes publish new versions through GitHub OIDC. npm and the two Rust crates also use their existing GitHub trusted-publisher workflows. Publication does not use a long-lived registry token fallback.

For a recent existing release, dispatch `pypi_publish.yml` from `main` with its existing `tag` (for example `v0.2.2`). The current controller builds that tag's exact source, compares the published sdist source and uploads only missing filenames with `skip-existing`. An early age check rejects releases with a surviving file older than 14 days, and staging rechecks before copying missing files. PyPI exposes file upload timestamps rather than a complete release-open status, so this preflight proves known expiry without guaranteeing upload eligibility. The expired 0.2.1 release needs the new 0.2.2 distribution; its original tag and files remain unchanged.
