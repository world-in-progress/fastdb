# FastDB 0.2.2 release record

Status: release preparation in progress on 2026-10-16. The maintainer authorized publication to PyPI, npm and crates.io, plus the matching Core SDK bundles and GitHub release. Hosted proof runs, immutable source identity and registry verification will be recorded after they complete.

This release supplies complete Python wheels after the attempted 0.2.1 backfill was [rejected by PyPI's 14-day upload limit](0.2.1-wheel-backfill.md). No portable format, ABI-117 or Core runtime implementation change is required. All language package versions and locks advance together to 0.2.2.

The Rust projection retains `AtomicUsize::fetch_update` with a local deprecation allowance: Rust 1.99 deprecated that alias, while its replacement `try_update` requires Rust 1.95. This keeps the existing edition-2024 compiler baseline and checked retain behavior; the [standard library documents both methods as aliases](https://doc.rust-lang.org/std/sync/atomic/struct.Atomic.html#method.fetch_update).

The required Python inventory is 20 wheels: cp312, cp313, cp314 and cp314t on macOS arm64/x86_64, manylinux_2_28 x86_64/aarch64, and Windows amd64; plus one sdist. Linux arm64 builds natively. Intel macOS cross-builds on arm64 and tests via Rosetta. Every installed wheel runs a small native payload write/read check and the existing payload suite. Inventory and source-bound hashes are checked before PyPI OIDC publication.

The complete release artifact set adds three Core SDK bundles (Linux x86_64, macOS arm64, Windows x64), two Rust crates and one TypeScript/WASM npm package: 27 package artifacts. The exact source must pass both Run Tests and Release Artifacts on `main` before tagging or publishing. PyPI uses the tag workflow; npm and crates.io consume the already tested candidate archives with the same source identity.

Manual Python backfills remain available for recent existing tags. An early age check rejects releases with a surviving file older than 14 days, and staging rechecks before copying missing files. PyPI exposes file upload timestamps rather than a complete release-open status, so this preflight proves known expiry without guaranteeing upload eligibility.
