# FastDB 0.2.1 release preparation

FastDB 0.2.1 adds the MSVC build correction from [PR #37](https://github.com/world-in-progress/fastdb/pull/37) and prepares native Windows x64 distributions. The Python package, Rust safe/raw crates, TypeScript package and native Core bundle share version 0.2.1 and one tested source commit. Published 0.2.0 artifacts and its tag remain unchanged.

The MSVC correction renames shadowing JSON iterators and makes the compile-time graph/record branches exhaustive. It preserves payload layout and the 117-symbol `fdb_payload_v1` ABI. Downstream C-Two [run 36034972057](https://github.com/Dsssyc/c-two/actions/runs/36034972057) proves the correction's source builds and CPython 3.12 consumers on Windows Server 2022/2025. That prior run does not prove new 0.2.1 release bytes or other Python ABIs.

Publication requires successful `tests.yml` and `release-artifacts.yml` runs for the exact merged source on `main`. The candidate must include the Windows Core DLL/import-library bundle and the supported Windows wheel set, alongside the existing Linux/macOS, source, Rust and TypeScript packages. The Windows native bundle must pass exact ABI inspection and an isolated Rust system-link consumer; wheel consumers must run the installed payload tests.

The PyPI, npm and crates.io dispatches consume the verified candidate run and source SHA; they do not rebuild packages. Rust publication uses the configured GitHub Trusted Publishers. A GitHub release and matching tag may only identify the tested source and verified artifacts. Successful publication and registry hash checks will be recorded here when complete.

C-Two must then move its dependency requirements and build source pin to this official release, rebuild its own release candidates and validate Windows installation against the published FastDB wheel.
