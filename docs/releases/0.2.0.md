## Release contract

- `fastdb4py`, `fastdb4ts`, `fastdb-sys` and `fastdb` use version 0.2.0; the Core/C ABI bundle belongs to the same release and source commit.
- Public payload ABI version 1 remains exactly 117 symbols. This release does not change payload schema, canonical identity or binary format.
- Native release evidence initially covers Linux x86-64 and macOS arm64; TypeScript uses the official wasm32 projection. Additional native platforms remain governed by Issue 0001 D4 until equivalent tests exist.
- Rust registry consumers use the matching platform Core bundle with `FASTDB_PAYLOAD_LINK_MODE=system` and an absolute `FASTDB_PAYLOAD_SYSTEM_LIB_DIR`. Checkout source mode is a separate development path.
- The release manifest records source SHA, hosted run identity, platform and artifact SHA-256. Registry jobs publish those verified bytes and treat an existing version as successful only after matching its artifact hash.
- Existing local candidate manifests remain historical. They are not rewritten as proof of this version or of a hosted run.

## Publication authentication

Version 0.2.0 used `PYPI_TOKEN` for PyPI, GitHub OIDC for npm, and a repository `CARGO_REGISTRY_TOKEN` secret for the first Rust publication. After both crates existed, their owner configured crates.io Trusted Publishers and authorized the Rust workflow's switch to GitHub OIDC.

Current Rust publication uses the pinned official `rust-lang/crates-io-auth-action` to obtain a short-lived token only when verified artifacts remain to upload. The action revokes that token in its post step. There is no long-lived-secret fallback. Both `fastdb` and `fastdb-sys` must trust owner `world-in-progress`, repository `fastdb`, workflow filename `crates_publish.yml`, with the environment field empty. The existing npm workflow identity is unchanged.

To verify authentication without publishing, dispatch `crates_publish.yml` from `main` with operation `verify-oidc`; no candidate run or source SHA is needed. Check both the token exchange and post-action revocation in the completed run. Exchange success proves a matching publisher exists; the registry does not return the token's permitted crate list, so this check cannot independently confirm both crate bindings or a new-version upload. Normal publication uses operation `publish` and requires the exact tested source SHA and successful artifact run ID. An already-published version with matching hashes skips authentication and upload, so that path alone cannot verify OIDC.

The OIDC operations apply to `main` after this workflow change and subsequent tags that contain it. The immutable `v0.2.0` tag keeps its original workflow, with no `operation` input and with token-secret authentication. Its publication is complete; the tag and release artifacts are not changed to retrofit OIDC.

## Local environment notes

On this machine the current command-line toolchain did not find the C++ standard headers through its default SDK search. Fresh native builds use an explicit installed macOS SDK and C++ include path through temporary environment/build flags. No machine-specific path is committed as a project build default.

Earlier local runs used macOS arm64 and AppleClang with ASan leak detection disabled; those runs did not prove LeakSanitizer behavior. The x86-64 C11 header check was a compilation check. The final Linux hosted run above supplies runtime and LeakSanitizer evidence. Local packages remain preparation artifacts; official publication used the clean source commit and hashes emitted by the hosted artifact workflow.

## Hosted feedback during preparation

PR [#35](https://github.com/world-in-progress/fastdb/pull/35) contains the complete foundation and release changes. The candidate build at `f1a115b7cf631152cea3b63c682ef41693469a3c` passed all eight artifact jobs, including both native bundles, twelve Python wheels, the sdist and TypeScript/WASM package. It predates the final notice and lifetime fixes and is not the publication input.

The Linux sanitizer run found a real legacy layer-builder leak. The parent now owns layers with `unique_ptr`; TypeScript's borrowed handles no longer destroy them independently. Apple `leaks` measured 363 leaked allocations before the repair and zero after it; the final hosted Linux LeakSanitizer run also passed without diagnostics. Python 344/344 and the rebuilt WASM TypeScript 58/58 tests passed after the ownership repair. Large graph semantic, exhaustive allocation-failure and 50,000-object cycle proofs now have separate CTest entries, with extra time allowed only for the instrumented large-cycle cases. No fixture size or fault-injection point was removed.

All distribution types now retain the repository's original third-party notices and compare them byte-for-byte in package checks. Registry workflows permit exact-source retries from the corresponding version tag after `main` advances; branch, tag/version, complete proof, run attempt and artifact hash checks still apply.
